# Creabra 面料库 V1 视觉参考交接说明

## 1. 文档用途

本仓库用于帮助技术开发团队理解 Creabra 面料库的业务流程、页面层级和主要交互，不是可上线的产品代码。

仓库中的面料、供应商、联系人、价格、任务进度和推荐结果均为虚构样例。页面中的上传、整理、保存和推荐交互用于展示预期体验，不代表数据库、AI、文件存储、权限或接口已经接通。

## 2. 阶段命名

产品阶段统一使用 **V1 / V2 / V3**，避免与工程问题严重性 P0 / P1 / P2 混淆。

### V1：300 款通用面料基础库

V1 的目标是建立经过人工核验的 300 款通用面料，打通以下主链路：

1. 导入色卡、图片、PDF、网页链接和基础清单。
2. 展示已确认、待补充、待确认、存在冲突和 AI 推测。
3. 由业务人员逐款核对后进入面料墙。
4. 支持面料找服装和服装找面料。
5. 真实库存候选与非库存概念建议始终分开展示。

V1 先使用可解释的条件筛选、业务状态和人工确认完成基础选料。在真实测试完成前，不对外展示精确分数或宣称已经达到智能精准匹配。

### V1 的 70% 验收指标

至少准备 30 组具有代表性的服装需求。每组需求返回三款最接近的真实库存面料，由面料专家或经验业务人员评审是否可以进入打样。

指标定义为：

> Top 3 候选中至少一款获专家接受的需求组数 ÷ 全部测试需求组数。

V1 验收底线为 **≥ 70%**，**80%** 作为后续优化目标。每组测试需保留需求、候选结果、专家判断、否决原因和日期，不使用页面上的样例分数代替真实验收。

### V2：数据驱动的双向推荐

V2 在 V1 真实数据和人工反馈基础上增加：

- 结合成分、克重、组织、功能、成本、起订量和交期进行推荐。
- 面料到服装、服装到面料的双向推荐。
- 记录打样结果、采购结果和人工否决原因，用于持续优化。
- 生成与面料方向相关的服装概念效果图。

概念效果图必须标明为“AI 概念效果”，不能被解读为对真实面料颜色、纹理、透明度、弹性或垂感的精确仿真。

### V3：AI 面料研发辅助

V3 将 AI 定位为面料研发的辅助者，而不是最终配方的决定者。AI 可以根据目标服装需求，输出：

- 候选成分及比例范围。
- 克重、纱支、组织、后整理和工艺方向。
- 预期效果、成立条件和不确定性。
- 打样、实验室检测和供应商确认计划。

面料性能不能只凭成分百分比精确确定。纱支、长丝/短纤、捻度、密度、编织结构、后整理、涂层、染色、厚度和批次差异都会影响结果。因此，V3 输出只能作为候选规格和检测计划，必须经面料工程师、供应商和实际测试确认，不能直接作为已验证的生产配方或工艺指令。

## 3. 前端文案边界

面向业务用户的页面只需要说明：

1. 用户现在需要做什么。
2. 系统展示了什么样例结果。
3. 用户下一步需要确认什么。

前端页面不展示：

- 后端处理流程、内部算法、权重、阈值、模型版本或规则库版本。
- 未经真实测试的精确置信度、匹配分数或“全自动”能力承诺。
- 技术日志、队列详情、调试状态或开发者说明。
- 真实供应商联系方式、内部底价、客户文件或其他敏感资料。

这些内容应分别进入内部技术文档、日志系统、管理设置或经授权的内部页面。

## 4. 本轮不包含的范围

本轮只收敛视觉原型的用户可见文案和产品阶段说明，不包含：

- 更换现有样例图片。
- 移动端适配。
- 登录、权限、企业数据隔离或脱敏机制。
- 数据库、文件存储、AI 服务、外部接口或生产配置。
- 300 款真实面料录入和上线发布。

上述内容需要由技术团队按风险级别另行设计、实施和审查。
